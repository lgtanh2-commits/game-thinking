Chiến Lược Kiểm Thử API

Unit test, integration test, contract test và performance test để đảm bảo chất lượng API

Tại Sao Kiểm Thử API Quan Trọng?

API là "hợp đồng" giữa provider và consumer — khi API lỗi, hàng chục ứng dụng phụ thuộc cùng lỗi theo. Không giống UI có thể sửa nhanh mà user không để ý, lỗi API ảnh hưởng trực tiếp đến tất cả integration và thường phát hiện muộn nhất. Kiểm thử API toàn diện không phải là lựa chọn — đó là điều kiện để API tin cậy đủ để publish.

Test Pyramid cho API

Chiến lược kiểm thử hiệu quả dựa trên nguyên tắc: nhiều test rẻ (unit) ở đáy, ít test đắt (E2E) ở đỉnh. Pyramid này áp dụng trực tiếp cho API testing:

Manual / Exploratory
End-to-End Tests
Contract Tests
Integration Tests
Unit Tests (Business Logic)

Các Loại Kiểm Thử API

1. Unit Testing — Kiểm Thử Đơn Vị

NhanhNhiều nhấtIsolate

Test từng hàm, method, business logic riêng lẻ mà không cần dependency thực (database, external service). Sử dụng mock/stub để thay thế dependency. Chạy trong milliseconds, có thể có hàng nghìn test case.

Mục tiêu: Validate business logic — tính toán giá, validate input, transform data. Không phải test HTTP layer hay routing. Tools: JUnit, pytest, Jest, Go test.

2. Integration Testing — Kiểm Thử Tích Hợp

Database thậtService thật

Test API thực sự qua HTTP, với database và external service thật (hoặc testcontainer). Verify endpoint hoạt động đúng từ đầu đến cuối trong environment kiểm soát được. Chạy chậm hơn unit test nhưng cover những bug mà unit test bỏ sót.

Ví dụ: Gọi POST /orders với body hợp lệ → expect 201 với orderId trong response, kiểm tra database có record tương ứng. Tools: Postman, RestAssured, Supertest (Node.js), pytest + httpx.

3. Contract Testing — Kiểm Thử Hợp Đồng

Consumer-DrivenBreaking Change Detection

Verify rằng API provider và consumer đồng thuận về "hợp đồng" — cấu trúc request/response. Consumer định nghĩa expectations, provider verify rằng họ đáp ứng. Phát hiện breaking change sớm nhất, trước khi code đến production.

Pact framework: Consumer tạo pact file mô tả những gì họ gửi/nhận. Provider verify pact file này. Nếu provider thay đổi response structure → pact test fail ngay, không cần deploy mới biết lỗi.

4. End-to-End Testing — Kiểm Thử Toàn Trình

Production-likeÍt nhất

Test full workflow thực tế: từ API call đầu tiên đến kết quả cuối cùng, qua tất cả service thật trong môi trường staging. Tốn kém nhất, chạy chậm nhất, brittle nhất — dành cho critical user journey chính.

Ví dụ: Full e-commerce checkout flow: tìm sản phẩm → thêm giỏ hàng → thanh toán → xác nhận đơn hàng → kiểm tra email, inventory update, payment record. Mỗi bước là API call thực.

5. Performance Testing — Kiểm Thử Hiệu Năng

Load TestStress TestSoak Test

Kiểm tra API hoạt động như thế nào dưới tải. Ba loại chính: Load test (traffic bình thường và cao điểm dự kiến), Stress test (tăng tải đến khi hệ thống fail — tìm điểm giới hạn), Soak test (traffic bình thường trong nhiều giờ/ngày — phát hiện memory leak).

Tools phổ biến: Apache JMeter, k6 (JavaScript-native, CI-friendly), Gatling (Scala DSL), Artillery (Node.js). Metrics quan trọng: throughput (req/s), latency percentiles (p50/p95/p99), error rate.

6. Security Testing — Kiểm Thử Bảo Mật

OWASPAutomated Scan

Tự động kiểm tra các lỗ hổng bảo mật trong API: SQL injection, broken authentication, excessive data exposure, BOLA/BFLA. Tích hợp vào CI/CD pipeline để phát hiện regression bảo mật sớm.

Tools: OWASP ZAP (automated scanning), Burp Suite (manual + automated), 42Crunch API Security (OpenAPI-based), Checkmarx, Snyk. Ưu tiên test theo OWASP API Top 10.

Viết API Test Hiệu Quả — Ví Dụ Thực Tế

Integration Test với Supertest (Node.js)

const request = require('supertest'); const app = require('../app'); const db = require('../db'); describe('POST /orders', () => { beforeEach(async () => { await db.clearOrders(); // Setup sạch trước mỗi test }); it('should create order and return 201 with orderId', async () => { const response = await request(app) .post('/v1/orders') .set('Authorization', `Bearer ${testToken}`) .send({ customerId: 'cust-123', items: [{ productId: 'prod-456', quantity: 2 }] }); expect(response.status).toBe(201); expect(response.body).toMatchObject({ id: expect.stringMatching(/^ord-/), status: 'pending', customerId: 'cust-123' }); // Verify database state const order = await db.findOrder(response.body.id); expect(order).toBeTruthy(); }); it('should return 400 for missing required fields', async () => { const response = await request(app) .post('/v1/orders') .set('Authorization', `Bearer ${testToken}`) .send({ customerId: 'cust-123' }); // Thiếu items expect(response.status).toBe(400); expect(response.body.code).toBe('VALIDATION_ERROR'); }); it('should return 401 without auth token', async () => { const response = await request(app) .post('/v1/orders') .send({ customerId: 'cust-123', items: [] }); expect(response.status).toBe(401); }); });

Performance Test với k6

import http from 'k6/http'; import { check, sleep } from 'k6'; export const options = { stages: [ { duration: '1m', target: 50 }, // Ramp up đến 50 users { duration: '5m', target: 50 }, // Giữ 50 users trong 5 phút { duration: '1m', target: 200 }, // Tăng lên 200 users (peak) { duration: '2m', target: 200 }, // Giữ peak { duration: '1m', target: 0 }, // Ramp down ], thresholds: { http_req_duration: ['p95<500'], // 95% requests < 500ms http_req_failed: ['rate<0.01'], // Error rate < 1% }, }; export default function () { const response = http.get('https://api.example.com/v1/products', { headers: { Authorization: `Bearer ${__ENV.API_TOKEN}` }, }); check(response, { 'status is 200': (r) => r.status === 200, 'response time < 500ms': (r) => r.timings.duration < 500, 'response has products': (r) => JSON.parse(r.body).items.length > 0, }); sleep(1); }

Tích Hợp Vào CI/CD Pipeline

Kiểm thử API hiệu quả nhất khi tự động chạy trong CI/CD:

  • Pre-commit hooks — unit test chạy local trước khi push (fast, ≤30s)
  • Pull Request CI — unit test + integration test + contract test. Gate: phải pass mới được merge
  • Staging deployment — E2E test, API security scan tự động sau khi deploy staging
  • Performance regression test — chạy nightly hoặc trước release lớn, so sánh với baseline
  • Production smoke test — sau mỗi production deployment, chạy tập test nhỏ (5-10 test) verify critical paths
Quy tắc: Test phải là first-class citizen, không phải afterthought. Nếu API thay đổi mà không có test fail — đó là dấu hiệu test coverage chưa đủ, không phải code tốt.

API Mocking — Test Khi Dependency Chưa Sẵn Sàng

Khi phát triển consumer trước khi provider API sẵn sàng, hoặc khi external API tốn tiền/không ổn định, mock server là giải pháp:

  • WireMock — Java-based mock server, configure qua JSON hoặc code, record & replay real API calls
  • Mockoon — GUI tool tạo mock API nhanh chóng, export thành Docker container
  • Prism (Stoplight) — sinh mock server tự động từ OpenAPI spec, validate request/response theo schema
  • MSW (Mock Service Worker) — intercept network request trong browser/Node.js, phù hợp với frontend test
