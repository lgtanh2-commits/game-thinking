Giới Thiệu về API

Hiểu bản chất của API: định nghĩa, lịch sử tiến hóa, phân loại và chuỗi giá trị kinh doanh

API Là Gì? — Ẩn Dụ Nhà Hàng

Cách dễ nhất để hiểu API là thông qua ẩn dụ nhà hàng. Khi bạn đến nhà hàng, bạn xem thực đơn để chọn món, rồi gọi phục vụ để đặt. Bạn có thể yêu cầu điều chỉnh đặc biệt — mức cay, thêm rau. Phục vụ ghi lại yêu cầu và chuyển vào bếp. Đầu bếp chế biến, phục vụ mang món ra bàn. Bạn kiểm tra, ăn, rồi để lại đánh giá.

Trong ẩn dụ này, mỗi thành phần đóng vai trò cụ thể:

  • Bạn là consumer của API — người gửi yêu cầu và nhận kết quả.
  • Phục vụ là API — nhận yêu cầu từ consumer, chuyển đến bếp, mang phản hồi về. Phục vụ là trung gian giao tiếp dữ liệu.
  • Thực đơn là tài liệu API — liệt kê những gì có thể gọi, điều kiện và giá cả. Phục vụ chỉ hiểu những gì ghi trong thực đơn.
  • Bếp là API server — xử lý yêu cầu theo nghiệp vụ, bạn không biết và không cần biết đầu bếp tên gì hay họ nấu thế nào. Bếp phục vụ theo chuẩn công thức, đảm bảo tính nhất quán.

Trong kỹ thuật, API (Application Programming Interface) là giao diện phần mềm xác định hợp đồng — cách hai ứng dụng giao tiếp: hành động có thể thực hiện, định dạng dữ liệu trao đổi, giao thức sử dụng. Triển khai bên trong có thể thay đổi, nhưng hợp đồng phải ổn định — đây là điểm mấu chốt phân biệt API với website.

Tiến Hóa của API (2000–2023)

Lịch sử web API bắt đầu từ năm 2000 và phát triển qua nhiều làn sóng công nghệ:

Năm 2000
Roy Thomas Fielding công bố luận án tiến sĩ "Architectural Styles and Design of Network-Based Software Architectures", đặt nền tảng lý thuyết cho REST. Cùng năm, Salesforce lần đầu trình diễn XML API tại IDG Demo 2000 — cột mốc API thương mại đầu tiên.
Tháng 11/2000
eBay ra mắt eBay API và eBay Developers Program, mở ra kỷ nguyên API cho thương mại điện tử và tích hợp đối tác.
Tháng 7/2002
Amazon Web Services ra mắt, cho phép bên thứ ba tìm kiếm và hiển thị sản phẩm Amazon qua XML. Đây là nền tảng của "nền kinh tế API".
2004–2006
Làn sóng mạng xã hội: Flickr API (8/2004), Facebook Developer Platform (8/2006), Twitter API (9/2006). API trở thành xương sống của thời đại Web 2.0. Amazon S3 (3/2006) và EC2 (9/2006) mở ra kỷ nguyên cloud computing.
Tháng 6/2005
Google Maps API ra mắt — một trong những API phổ biến nhất mọi thời đại, với hơn một triệu trang web tích hợp.
2009–2010
Kỷ nguyên mobile: Foursquare (3/2009), Apple iPhone 3G App Store (6/2009), Instagram (10/2010). API trở thành động lực của nền kinh tế app. REST API và JSON thống trị.
2012
API trưởng thành. REST APIs thống lĩnh thị trường nhờ tính đơn giản và khả năng mở rộng. JSON trở thành tiêu chuẩn thực tế cho trao đổi dữ liệu.
2015
Facebook giới thiệu GraphQL như một thay thế cho REST — cho phép client truy vấn đúng dữ liệu cần, giảm over-fetching và under-fetching.
2020–2023
COVID-19 tăng tốc chuyển đổi số. OpenAPI, AsyncAPI, gRPC chuẩn hóa đặc tả API. Cloud native và microservices bùng nổ. ChatGPT API (2023) mở ra thời đại tích hợp AI/LLM.

API Khác Website Ở Chỗ Nào?

Website xuất bản thông tin để người dùng đọc — giao diện, bố cục, nội dung có thể thay đổi bất cứ lúc nào mà không cần báo trước. Không có hợp đồng cứng. Khi website redesign, người dùng chỉ cần thích nghi với giao diện mới.

API ngược lại, có hợp đồng cứng. Các ứng dụng phụ thuộc vào hợp đồng này. Chương trình không linh hoạt như người — nếu hợp đồng API thay đổi, tất cả ứng dụng đang dùng API đó đều bị ảnh hưởng. Do đó, thay đổi API phải được quản lý cẩn thận, có versioning và backward compatibility.

Phân Loại API: Public, Private, Partner

🌐 Public API

Mở cho toàn bộ cộng đồng nhà phát triển. Tối đa hóa adoption và đổi mới. Ví dụ: Google Maps, Twitter, OpenWeather. Thách thức: quản lý bảo mật và phiên bản phức tạp.

🤝 Partner API

Dành cho đối tác B2B có thỏa thuận hợp tác. Kiểm soát truy cập chặt hơn public API. Ví dụ: API tích hợp giữa ngân hàng và fintech.

🏢 Private/Internal API

Chỉ dùng nội bộ tổ chức — kết nối hệ thống, xây dựng mobile app doanh nghiệp. Chiếm phần lớn "núi băng" API không nhìn thấy được. Mọi Facebook, Google đều có hàng nghìn internal API.

Private API thực chất là phần lớn "núi băng" trong nền kinh tế API — chúng không xuất hiện trên internet nhưng vận hành toàn bộ hệ thống doanh nghiệp. Mỗi doanh nghiệp xây dựng public API đều bắt đầu từ private API nội bộ.

Đặc Tính của Một API Tốt

API provider cần cung cấp thông tin đầy đủ về API của mình:

  • Hành động (Actions) — API có thể thực hiện chức năng nghiệp vụ gì
  • Vị trí (Location) — URI/endpoint để truy cập tài nguyên
  • Tham số (Parameters) — tên tham số đầu vào/đầu ra, định dạng dữ liệu (JSON/XML), kiểu dữ liệu
  • Giao thức (Protocol) — HTTP/HTTPS, FTP/SFTP, JMS, v.v.
  • Bảo mật (Security) — cơ chế xác thực: API key, OAuth, mTLS, xác thực đa yếu tố
  • SLA — response time, throughput, availability cam kết
  • Rate Limits — giới hạn số lượng request trong khoảng thời gian nhất định
  • Ràng buộc pháp lý — điều khoản thương mại, phí, yêu cầu branding
  • Tài liệu (Documentation) — hỗ trợ nhà phát triển hiểu và sử dụng API

Ngoài ra, API provider có thể cung cấp thêm: developer portal, sample code, community forum, testing tools, health dashboard.

Các Nhóm API Phổ Biến theo Lĩnh Vực

Hiện nay, hầu hết ngành công nghiệp đều có các API nổi bật:

  • Mạng xã hội & messaging: Facebook, Instagram, LinkedIn, X (Twitter) — truy cập dữ liệu xã hội, người dùng, nội dung
  • Bản đồ & địa điểm: Google Maps, Mapbox, OpenStreetMap — routing, geolocation, tìm kiếm địa điểm
  • Thanh toán: Stripe, PayPal, Google Pay, Razorpay — xử lý giao dịch, subscription, ví điện tử
  • Giao tiếp & cộng tác: Twilio, Slack, Zoom, Microsoft Teams — SMS, voice, video, alerting
  • Thương mại điện tử: Amazon, eBay, Shopify, Etsy — quản lý đơn hàng, sản phẩm, giỏ hàng
  • Y tế: Cerner, Allscripts, OpenFDA — hồ sơ bệnh nhân, lịch sử y tế, thiết bị đeo tay
  • Vận tải & du lịch: Uber, Lyft, Amadeus, Skyscanner — đặt vé, định tuyến, tra cứu thời gian thực
  • Chính phủ & dữ liệu công: UN Data, NASA, Census Bureau, World Bank — dữ liệu kinh tế, xã hội, khoa học
  • AI & Machine Learning: TensorFlow, OpenAI, Google Cloud AI — xử lý ngôn ngữ tự nhiên, nhận dạng hình ảnh, chatbot
  • Cloud: AWS, Azure, Google Cloud — quản lý tài nguyên điện toán đám mây theo chương trình

Lưu ý quan trọng: mọi web service đều là API, nhưng không phải API nào cũng là web service. REST API sử dụng HTTP verbs (GET, POST, PUT, DELETE) để thực hiện các thao tác CRUD trên tài nguyên, dùng URL sạch (RESTful URLs) và JSON là định dạng ưa chuộng vì nhẹ và dễ đọc với con người.

API vs SOA: Hợp Tác, Không Đối Lập

Service-Oriented Architecture (SOA) là kiến trúc doanh nghiệp tập trung vào việc xây dựng lại các dịch vụ có thể tái sử dụng, thường dùng SOAP/WSDL, được mô tả trong UDDI registry. SOA giúp agility và pace của delivery dịch vụ nội bộ.

API tập trung hơn vào tiêu dùng — làm cho dịch vụ dễ sử dụng, thân thiện với developer, dễ adopt qua HTTP/REST/JSON. API không thay thế SOA mà là lớp trên SOA — APIs "đóng gói" lại các dịch vụ SOA để chia sẻ dễ dàng hơn.

Sự khác biệt thực sự giữa SOA và API nằm ở mục tiêu và quản trị: SOA tập trung kiểm soát và tích hợp nội bộ; API tập trung adoption và đổi mới từ bên ngoài. Cùng nhau, chúng tạo thành nền tảng hoàn chỉnh của doanh nghiệp kỹ thuật số.

Chuỗi Giá Trị API

Để hiểu giá trị kinh tế của API, cần theo dõi chuỗi giá trị từ tài sản doanh nghiệp đến người dùng cuối:

doanh nghiệp

→

→

→
App
→
End User

Thành công của chiến lược API phụ thuộc vào tất cả mắt xích trong chuỗi giá trị. API provider cần hiểu giá trị tài sản và thiết kế interface tốt nhất để expose nó. Developer phải hiểu tài sản và interface để xây app đáp ứng nhu cầu người dùng. App phải dễ dùng và mang lại giá trị thực sự. Chỉ khi tất cả stakeholders đều hiểu mục tiêu kinh doanh cốt lõi, API mới thành công.

Động Lực Kinh Doanh của API

API là nền tảng của kinh doanh kỹ thuật số. Các động lực kinh doanh chính thúc đẩy doanh nghiệp xây dựng API:

  • Phát triển khả năng và cơ hội kinh doanh mới
  • Mở kênh phân phối và dòng doanh thu mới
  • Cải thiện tiếp cận khách hàng và tăng loyalty
  • Đổi mới tại biên của kinh doanh (edge innovation)
  • Tăng tốc thời gian ra thị trường
  • Nâng cao hiệu quả vận hành và kiểm soát
  • Tăng traffic và thúc đẩy dự án nội bộ

Mô Hình Kinh Doanh API

API tạo ra doanh thu thông qua nhiều mô hình khác nhau:

  • Freemium / Free
    API miễn phí / Freemium — Cung cấp API hoàn toàn miễn phí để tối đa hóa adoption. Khách hàng trả phí để có giới hạn cao hơn hoặc tính năng nâng cao. Ví dụ: Google Maps miễn phí đến 25,000 requests/ngày.
  • Pay-as-you-go
    Trả theo mức dùng — Consumer trả tiền tương ứng với số lần gọi API, giao dịch hoặc dữ liệu sử dụng. Mô hình linh hoạt cho doanh nghiệp nhỏ và startup.
  • Subscription
    Đăng ký định kỳ — Phí cố định hàng tháng/năm theo gói, có thể phân tầng theo mức độ sử dụng và tính năng. Tạo doanh thu ổn định và dự báo được.
  • Transaction Fee
    Phí giao dịch — API provider thu một phần phí từ mỗi giao dịch thành công qua API. Phổ biến trong thanh toán, đặt vé, thương mại điện tử.
  • Data Licensing
    Cấp phép dữ liệu — Doanh thu từ việc cấp phép dữ liệu hoặc tính phí truy cập bộ dữ liệu premium cho nghiên cứu, phân tích.
  • Affiliate
    Giới thiệu & hoa hồng — API provider kiếm hoa hồng khi người dùng API đăng ký dịch vụ đối tác thành công.
Nhiều API provider kết hợp hai hay nhiều mô hình để đa dạng hóa nguồn thu và phục vụ các phân khúc khách hàng khác nhau.
