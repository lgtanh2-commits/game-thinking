Quản Trị API

Thiết lập chính sách, tiêu chuẩn và quy trình để quản lý toàn bộ vòng đời API ở quy mô tổ chức

Quản Trị API Là Gì?

Quản trị API (API Governance) là tập hợp chính sách, tiêu chuẩn, quy trình và vai trò để đảm bảo rằng API trong tổ chức được thiết kế, phát triển, vận hành và retire một cách nhất quán, an toàn và hiệu quả.

Khi tổ chức có 5 API, governance là vấn đề của team. Khi có 500 API do 20 team khác nhau xây dựng, governance là điều kiện sống còn để tránh chaos: API không nhất quán, bảo mật không đồng đều, không ai biết API nào tồn tại, không ai chịu trách nhiệm khi có incident.

Các Trụ Cột Quản Trị API

1. API Design Standards — Tiêu Chuẩn Thiết Kế

Tập tài liệu định nghĩa cách mọi API trong tổ chức phải được thiết kế: naming convention, URL structure, HTTP method usage, error format, pagination, versioning, authentication. Đây là "constitution" của API program.

  • Style guide viết dưới dạng do/don't với ví dụ cụ thể
  • Linting tool tự động enforce (Spectral, Stoplight) — check OpenAPI spec
  • Design review checklist trước khi API được approve publish
  • Ví dụ API "chuẩn mực" làm reference cho team mới

2. API Lifecycle Management — Quản Lý Vòng Đời

Quy trình chính thức cho mỗi giai đoạn: từ ideation đến design review, đến publish, đến deprecation và sunset. Không có API nào được publish mà không qua review, không có API nào bị tắt đột ngột.

  • Design review gate: bắt buộc trước khi bắt đầu implementation
  • Security review: OWASP checklist, threat modeling cho mỗi API mới
  • API Registry: catalog tập trung — mọi API đều được đăng ký, có owner
  • Deprecation policy: quy trình và timeline bắt buộc cho mọi sunset

3. Security & Compliance Policies — Chính Sách Bảo Mật

Quy định bảo mật tối thiểu mà mọi API phải đáp ứng: authentication scheme nào được phép, rate limiting tối thiểu, PII handling, data retention, audit logging. Không phải option — là requirement.

  • Authentication: mọi API phải dùng OAuth 2.0 hoặc JWT (API key chỉ cho internal)
  • PII: không được log personal data trong request/response log
  • TLS: chỉ TLS 1.2+, tự động reject kết nối cũ hơn
  • Rate limiting: mọi public API phải có rate limit, không exception
  • Data classification: mỗi API endpoint phải được classify (public/internal/confidential)

4. API Ownership & Accountability — Sở Hữu và Trách Nhiệm

Mỗi API phải có owner rõ ràng — team hoặc cá nhân chịu trách nhiệm về chất lượng, uptime, documentation, và deprecation. "API không có owner là API đang chết chậm."

  • API Registry field "owner" là bắt buộc — tên team và contact cụ thể
  • On-call rotation: ai chịu trách nhiệm khi API có incident ngoài giờ
  • SLA commitments: owner cam kết uptime, latency, support response time
  • Review cycle: owner review usage data và health hàng tháng

5. API Review Process — Quy Trình Review

Cơ chế kiểm soát chất lượng tập trung: Design Review Board (DRB) hoặc API Center of Excellence (CoE) review mọi API mới và breaking change quan trọng trước khi publish.

  • Tiêu chí submit: OpenAPI spec đầy đủ, security assessment, test plan
  • Review SLA: phản hồi trong 5 ngày làm việc, không block team
  • Approve vs Request Changes vs Reject với lý do rõ ràng
  • Fast-track cho hotfix và minor changes

API Review Process Flow

Design Proposal → Design Review → Security Review → Implementation → QA Review → Staging → Production

API Governance Maturity Model

LevelĐặc ĐiểmDấu Hiệu Nhận Biết
Level 1: Ad-hoc Không có tiêu chuẩn, mỗi team tự quyết định API không nhất quán, không biết bao nhiêu API tồn tại, không ai chịu trách nhiệm
Level 2: Defined Có style guide và review process, nhưng áp dụng không đều Một số API follow standard, nhiều API là exception, review tốn nhiều thời gian
Level 3: Managed Governance tự động hóa phần lớn, metrics rõ ràng, ownership rõ Linting tự động, API registry đầy đủ, SLA được monitor, review nhanh
Level 4: Optimizing Continuous improvement, AI-assisted governance, developer-first culture Governance giúp team nhanh hơn, không làm chậm; self-service hoàn toàn

Policies Thực Hành

Naming Convention

Resources dùng danh từ số nhiều (orders, not order). URL dùng kebab-case (product-categories, not productCategories). Version trong URL (/v1, /v2). Query params dùng camelCase.

Error Response Format

Tất cả error đều trả về: { "code": "ERROR_CODE", "message": "Human readable", "details": [...], "traceId": "..." }. Không trả về stack trace trong production.

Pagination Standard

Dùng cursor-based pagination cho list lớn (cursor/limit), offset cho list nhỏ (page/pageSize/totalCount). Không trả về toàn bộ collection không paginated.

Deprecation Timeline

Thông báo deprecation tối thiểu 6 tháng trước. Maintain song song cả hai version trong period này. Thông báo qua email, header, developer portal.

Rate Limiting Minimum

Public API: tối thiểu rate limit theo API key. Internal API: tối thiểu circuit breaker. SLA tier higher → higher limits, không phải không limit.

Data Residency

API xử lý data của EU residents phải comply GDPR. Data không rời khỏi region khi có yêu cầu data residency. Log PII phải được mask hoặc encrypt.

API Governance Tooling

  • Spectral — open-source linter cho OpenAPI spec, enforce style rules tự động trong CI
  • Stoplight Platform — thiết kế API, style guide enforcement, cộng tác team
  • Apigee / Kong / Azure APIM — gateway enforcement: policies apply tự động ở runtime
  • Backstage (Spotify) — internal developer portal, service catalog, API registry
  • 42Crunch — API security audit tự động, scan OpenAPI spec và live traffic
Governance hiệu quả là governance vô hình — developer làm đúng mà không cần nghĩ về governance vì tools và process đã dẫn dắt họ đến quyết định đúng một cách tự nhiên.
